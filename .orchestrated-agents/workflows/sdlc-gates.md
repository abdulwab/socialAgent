# SDLC Gates

Every bead must tailor these gates to its stage. A gate can be marked **Applicable**, **Not Applicable**, or **Already Satisfied**, but it must not be silently omitted.

## Lifecycle Coverage

1. Intake and scope
2. Business or mission analysis
3. Stakeholder needs
4. Requirements definition
5. Architecture impact
6. Design definition
7. Risk management
8. Security and privacy analysis
9. Data and ownership analysis
10. Implementation plan
11. Construction or configuration
12. Integration impact
13. Verification strategy
14. Validation against user need
15. Documentation and handoff
16. Release or transition readiness
17. Operations, observability, and support
18. Maintenance, rollback, and disposal
19. Compliance or policy impact
20. Process improvement opportunity

## Required Output

Role Selector must comment a lifecycle matrix before Maker Engineer starts implementation. (The "SDLC Process Architect" is a debate perspective the Role Selector simulates, not a separate role.)

For each gate:

- Applicability
- Required roles
- Evidence expected
- Skip reason, if not applicable

## Evidence Standard

Evidence can be tests, command output, code references, design reasoning, source links, or explicit user acceptance criteria. "Looks fine" is not evidence.
